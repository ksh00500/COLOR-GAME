# Tango 그래픽 시스템

Tango의 그래픽 방향은 `원목 보드게임의 물성 + 절제된 모던 연출`이다. 효과는 장식보다 수의 결과를 설명해야 하며, 웹과 Android에서 같은 React 렌더러와 타이밍을 사용한다.

## 핵심 원칙

- 게임판과 타일의 재질을 가리지 않는다.
- 배치, 연결, 득점을 동시에 강조하지 않고 순서대로 보여준다.
- 큰 입자, 반복 방사형 링, 화면을 가로지르는 광선은 기본 연출에서 사용하지 않는다.
- 색만으로 상태를 전달하지 않는다. 색각 보조 도형과 기존 판정 정보는 항상 유지한다.
- 상점·도감 미리보기는 실제 게임과 같은 색, 선 굵기, 표현 강도를 사용한다.
- WebGL을 사용할 수 없는 환경에서도 타일 안착과 점수 텍스트는 CSS로 남는다.

## 공통 시퀀스

1. **배치 안착 (260ms)**: 타일이 짧게 내려앉고 얇은 윤곽이 한 번 나타난다.
2. **연결 확인 (390ms)**: 득점 셀 안쪽에 1px 전후의 선과 낮은 투명도의 표면색을 순차 표시한다.
3. **점수 정리 (510ms 내외)**: 실제 획득 점수를 작은 캡슐형 레이블로 표시하고 연결 윤곽을 정리한다.

전체 시퀀스는 일반적으로 1.2초 안에 끝나며 다음 수의 입력과 게임판 판정을 막지 않는다.

## 스킨 변주 한도

- `default`: 기본 안착과 연결 윤곽만 사용한다.
- `sweep`: 연결 셀의 표시 순서만 한 방향으로 바꾼다.
- `wash`: 연결 셀 내부의 표면색을 조금 더 보이게 한다.
- `glint`: 연결 윤곽을 소폭 선명하게 한다.
- `lift`: 득점 정리 시 윤곽이 짧게 위로 이동한다.

프리셋은 공통 시퀀스의 순서와 지속 시간을 깨지 않는다. 새 효과도 이 한도 안에서 색, 순서, 미세 이동만 변주한다.

## 렌더링과 성능

- PixiJS 캔버스는 게임판 위의 입력 불가 오버레이로만 사용한다.
- 캔버스 해상도는 기기 배율 2배를 상한으로 둔다.
- 한 번에 배치 셀 1개와 득점 셀만 그리며, 시퀀스 종료 후 그래픽 객체를 즉시 제거한다.
- `prefers-reduced-motion`에서는 WebGL 오버레이를 숨기고 1ms CSS 상태 전환만 사용한다.
- 컴포넌트 해제, 새 수 입력, 화면 전환 시 이전 애니메이션을 취소한다.

## 적용 범위

- 완료: FX Lab, 실제 게임판의 배치·득점 연출, 상점·도감의 배치·득점 미리보기.
- 유지: 보드 테마, 타일 스킨, 색각 보조 도형, 판정 범위.
- 별도 개편: 승리 화면은 게임판 FX와 수명주기와 목적이 달라 독립 시스템으로 관리한다.

## 검수 기준

- 375×812와 320px 폭에서 캔버스가 게임판 밖으로 넘치지 않는다.
- 배치 효과와 득점 효과가 같은 프레임에 중복 폭발하지 않는다.
- 득점 레이블은 제거된 타일 수가 아니라 실제 획득 점수를 표시한다.
- 다크·라이트 테마 모두에서 윤곽이 보이되 타일보다 먼저 눈에 띄지 않는다.
- WebGL 초기화 실패가 게임 진행이나 React 렌더링 오류로 이어지지 않는다.
